The first warning (no line number) is emitted when =epdh.el= is loaded

itself.  The remaining seven are byte-compiler warnings.

* Analysis

** =buffer-substring= as obsolete generalized variable (line 131)
In =epdh/emacs-lisp-macroreplace=:

#+BEGIN_SRC elisp
(setf (buffer-substring beg end) (pp-to-string expansion))
#+END_SRC

=buffer-substring= as a generalized variable for =setf= is obsolete.
Replacement: =(delete-region beg end) (insert ...)= or
=(replace-region-contents beg end ...)=.

** =called-interactively-p= with 0 arguments (line 107)
In =epdh/byte-compile-and-load-directory=:

#+BEGIN_SRC elisp
(if (or (not (called-interactively-p))
#+END_SRC

=called-interactively-p= requires one argument (a symbol, typically
='interactive= or ='any=).  The zero-argument call was never correct;
older Emacs may have tolerated it.

** =byte-compile-file= with 2 arguments (line 113)
In =epdh/byte-compile-and-load-directory=:

#+BEGIN_SRC elisp
(byte-compile-file file 'load)
#+END_SRC

=byte-compile-file= accepts only one argument (=file=).  The optional
=load= argument was removed.  To compile and load: call
=byte-compile-file= then =load= the resulting =.elc=.

** Docstring wider than 80 characters (line 137)
In =bench= macro: the docstring's first line exceeds 80 characters.
Cosmetic; reflow the docstring.

** =second=, =third=, =fourth= not known to be defined (lines 238, 242, 243)
In =bench-multi= result formatting.  These are =cl= library accessors
(=cl-second=, =cl-third=, =cl-fourth=).  =epdh.el= does not
=(require 'cl-lib)= at compile time, so the byte-compiler cannot see
them.  Fix: add =(require 'cl-lib)= to =epdh.el=, or use the =cl-=
prefixed names.
